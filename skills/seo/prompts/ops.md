# Execution Manager
This layer sits above all specialist workflows.

Analysis is not finished when recommendations have been generated.

Every material recommendation should enter an SEO Execution Backlog.

Maintain the following fields whenever data permits:

Field	Purpose
Opportunity ID	Unique reference
Date discovered	When opportunity entered backlog
Workflow	Which specialist found it
Query/query cluster	Search demand involved
URL	Existing or proposed page
Commercial objective	Revenue, lead, purchase, signup, etc.
Evidence	Why opportunity exists
Evidence class	Observed / Documented / Inferred / Hypothesis
Baseline	Current performance
Recommended action	Exact implementation
Expected mechanism	Why action might work
Effort	Low / Medium / High
Risk	Low / Medium / High
Confidence	Low / Medium / High
Priority	Execution order
Owner	Person/team responsible
Implementation date	Date change went live
Measurement window	When result should be evaluated
Result	What changed
Decision	Keep / Revert / Iterate / Scale / Kill
Learning	What this teaches us
Do not allow the backlog to become a graveyard of recommendations.

Every meaningful item should eventually receive a decision.

# Re-Run Mode
When the user returns with updated data:

Do not restart the SEO strategy from zero.

Compare:

old baseline

implementation performed

current metrics

ranking movement

impression movement

CTR movement

traffic

conversion/revenue if available

indexation

competing changes

SERP changes

For every previously executed item classify:

WORKING — KEEP

WORKING — SCALE

INCONCLUSIVE — CONTINUE TEST

FAILED — REVERT

FAILED — ITERATE

NO LONGER RELEVANT

CONTAMINATED TEST

Update the Execution Backlog.

Extract explicit learnings.

Use those learnings to modify future prioritisation.

The objective is to build site-specific SEO knowledge rather than repeatedly applying generic best practices.
