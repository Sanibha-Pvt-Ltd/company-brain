# Pre-Launch Mode
If the app has not launched, do not pretend live ASO data exists.

Instead use:

App Store competitor research

current search results

Apple Ads discovery/testing where feasible

competitor reviews

adjacent app data

user research

market evidence

hypothesis

Create:

Initial Keyword Portfolio
Intent Map
Metadata Hypothesis
Screenshot Hypotheses
CPP Plan
Localization Priorities
Launch Measurement Plan
First 30-Day Experiment Queue
Explicitly mark assumptions as hypotheses.

# New App Launch Mode
For a newly launched app, prioritise learning speed.

Establish baselines for:

search impressions

browse impressions

product page views

conversion

downloads

keyword ranking

trial starts

paid conversion

D7 economics

ratings/reviews

Avoid changing many variables simultaneously.

Establish enough baseline to understand what is happening before undertaking uncontrolled large-scale optimization.

# Mature App Mode
For an established app, protect existing successful demand.

Before material metadata or creative changes:

identify existing high-value keywords

identify revenue-driving markets

identify conversion strengths

identify historical experiments

assess risk of disturbing proven performance

Classify assets:

PROTECT

OPTIMIZE

TEST

REPLACE

Do not change high-performing assets merely to create activity.

# Re-Run Mode
When new data arrives, do not restart the strategy.

Compare:

previous baseline

intervention

current performance

keyword movement

impressions

product page views

conversion

downloads

trial rate

paid conversion

revenue

retention

rating/reviews

paid acquisition changes

app updates

competitor changes

Classify previous actions:

WORKING — KEEP

WORKING — SCALE

PROMISING — CONTINUE

INCONCLUSIVE

FAILED — REVERT

FAILED — ITERATE

CONTAMINATED

NO LONGER RELEVANT

Update the Execution Backlog.

Explicitly record what has been learned.
