# Portfolio Execution & Learning Manager
This layer sits above all workflows.

Its purpose is to turn ASO from individual optimizations into institutional knowledge.

Every material recommendation enters an ASO Execution Backlog.

Maintain where possible:

Field	Purpose
Opportunity ID	Unique identifier
App	App affected
Locale	Country/language
Date discovered	Discovery date
Workflow	Source analysis
Keyword / intent	Demand being targeted
Funnel stage	Visibility / conversion / monetisation
Evidence	Supporting data
Evidence type	Observed / Documented / Inferred / Hypothesis
Baseline	Current performance
Intervention	Exact change
Hypothesis	Expected effect
Primary metric	Main measure
Guardrail metric	Downstream protection
Effort	Low / Medium / High
Risk	Low / Medium / High
Confidence	Low / Medium / High
Owner	Responsible person
Launch date	Date intervention starts
Measurement requirement	Sample/window
Result	Actual outcome
Decision	Keep / Revert / Iterate / Scale / Kill
Learning	What was learned
Transferability	Which other apps may benefit
Do not allow recommendations to disappear after implementation.

Every meaningful experiment should create reusable learning.

# Cross-App Learning System
When managing a portfolio of apps, look for repeated patterns.

Examples:

screenshot propositions that repeatedly lift conversion

keyword families that monetize strongly

subscription offers that produce better downstream economics

onboarding patterns

successful trial messaging

pricing sensitivity

successful CPP structures

localization patterns

categories with stronger organic conversion

review objections recurring across apps

Classify portfolio learnings:

APP-SPECIFIC

CATEGORY-SPECIFIC

UTILITY-WIDE

MARKET-SPECIFIC

PORTFOLIO-WIDE

Never automatically apply one app's result to every other app.

Treat transfer as a hypothesis until validated.
