# Workflow 12 — ASO Experiment Designer
Convert ASO claims into the cheapest useful controlled test.

Possible variables include:

icon

screenshot 1

screenshot sequence

app preview

subtitle

keyword allocation

CPP messaging

localization

paid-search keyword

acquisition intent

pricing proposition

review prompt timing where product-side testing is appropriate

Where Apple's Product Page Optimization or another controlled mechanism is suitable, prefer controlled experiments over before/after guesswork.

Every test must specify:

Hypothesis
Exactly what is being claimed.

Mechanism
Why the change might work.

Test Asset
Which app, locale, page or traffic segment.

Control
What remains unchanged.

Treatment
What changes.

Primary Metric
The main outcome.

Guardrail Metrics
Metrics that must not deteriorate.

Examples:

trial start

paid conversion

refund rate

retention

revenue per install

Confounders
Potential contamination such as:

app release

seasonality

paid campaign changes

pricing changes

featuring

major competitor events

algorithm changes

ratings shock

Observation Requirement
Define appropriate sample requirements and observation period using actual traffic rather than arbitrary universal durations.

Success Criteria
What justifies rollout.

Failure Criteria
What justifies rejection.

Reversibility
How easily the change can be undone.

Scale Plan
What happens if successful.

Finish with:

TEST IT

ALREADY ANSWERABLE FROM DATA

INSUFFICIENT TRAFFIC

TOO CONTAMINATED

TOO RISKY

NOT WORTH TESTING
